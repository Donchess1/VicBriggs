VICBRIGGS WEBSITE UPDATE — CHRONOLOGICAL PROJECT REGISTER

WHAT CHANGED
1. The Site Editor project form now captures: Project description, Client, Month, Year, and Project execution status (Completed or In Progress).
2. The CMS publication state remains separate: projects are still saved as Draft and must be Published before appearing publicly.
3. The public register now displays: S/N | DESCRIPTION OF ACTIVITIES | CLIENT | PERIOD OF EXECUTION | STATUS.
4. Projects with structured dates are ordered newest first by year and month. Records without a structured date are retained and placed after dated records.
5. S/N is generated from the visible sorted order, including across pagination. It is not an editable database field.
6. Existing free-text period values are preserved. Existing records are not assigned guessed months, years, or execution statuses; review and update them in Site Editor when the correct information is known.
7. Soft-delete, publish/unpublish, and the existing media-management functions remain in place.

DATABASE MIGRATION — REQUIRED BEFORE DEPLOYMENT
1. Back up the D1 database currently bound to the Vicbriggs Pages project.
2. Apply migrations/0005_project_chronology.sql to that same database. Example using Wrangler:
   npx.cmd wrangler d1 execute <DATABASE_NAME> --remote --file=migrations/0005_project_chronology.sql
   Replace <DATABASE_NAME> with the actual D1 database name. Do not guess it.
3. Confirm the migration succeeds before deploying the website files. The API now reads the new month, year, and execution_status columns.
4. Deploy the website folder to the existing Cloudflare Pages project.
5. Sign in at /admin, create a test project, confirm it is saved as Draft, publish it, and verify it appears on /projects.html in newest-first order. Then remove the test record.

IMPORTANT
- Do not re-run migrations/0004_projects.sql if it has already been applied. Apply only the new 0005 migration to the existing database.
- This package does not execute migrations or deploy to Cloudflare.
- Historical records with missing structured dates/statuses remain visible if published; their old period text is shown and status appears as an em dash until reviewed and updated.
